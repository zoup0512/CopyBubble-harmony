## 根因

设置页「桌面悬浮气泡」开关无法关闭(拨 OFF 后开关弹回 ON、气泡还在)。根因是 ArkUI `@Builder` 的响应式陷阱:

`SettingsPage.SwitchRow` 是个 `@Builder`,内部 `Toggle({ isOn: $$.value })` 的 `$$.value` 在首次构建后被固定为快照值(`true`),不随 `this.floatBubble` 变化(`UiModels.ets:1-4` 的注释其实已经预警过这一点)。拨动 OFF 时:
1. `onChange(false)` → 异步 `setFloatBubble(false)` 开始执行
2. ArkUI 发现 `Toggle.isOn` 仍是快照值 `true` → **强制弹回 ON**
3. 弹回 ON 触发二次 `onChange(true)` → `setFloatBubble(true)` → 重建气泡
4. 结果:开关 ON、气泡还在

`setFloatBubble` 是唯一异步开关处理(去重/震动都同步),异步间隙放大了这个效果。关闭分支本身的落盘/销毁逻辑是正确的——问题在 UI 层把状态又拨了回去。去重/震动两个开关走同一个 `@Builder`,有同样的潜在问题。

## 修复方案(改为子组件)

把 `@Builder SwitchRow` 重构为独立 `@Component SwitchRow` 子组件,建立真正的数据绑定,`Toggle.isOn` 能随数据源响应式刷新。

### 改动文件

1. **新建 `entry/src/main/ets/components/SwitchRow.ets`** —— 独立 `@Component` 子组件
   - `@Prop title/desc: string`、`@Prop value: boolean`(父→子,响应式)、`onChange: (v: boolean) => void`(子→父回调)
   - `Toggle({ type: ToggleType.Switch, isOn: this.value })` —— `this.value` 是 `@Prop`,响应式正常
   - 样式从旧 `@Builder` 原样搬过来

2. **修改 `entry/src/main/ets/pages/SettingsPage.ets`**
   - `import { SwitchRow } from '../components/SwitchRow'`
   - 删除旧 `@Builder SwitchRow($$: SwitchRowParam)`(第 124-148 行)
   - 三处调用点改为普通子组件调用:`this.SwitchRow({...})` → `SwitchRow({...})`
   - 删除 `import { SwitchRowParam }` 中对该类的引用

3. **修改 `entry/src/main/ets/common/UiModels.ets`**
   - 删除已无用的 `SwitchRowParam` 类(第 6-11 行)

### 验证

- 用 hvigorw 编译检查 ArkTS 改动无误(`assembleHap --no-daemon`,stderr 重定向到日志读取真实错误)
- 预期:三个开关都能正常切换;悬浮气泡拨 OFF 后开关停 OFF + 气泡消失;拨 ON 后权限弹窗/气泡重建正常
