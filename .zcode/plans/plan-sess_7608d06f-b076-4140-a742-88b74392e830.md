# 双窗口架构：根治悬浮窗拖拽闪烁 + 保留下层触摸穿透

## 背景与根因（已确认）

两个系统层约束互相矛盾，单窗口无解：
1. **窗口 resize 会让 WMS 重建 surface，中间帧覆盖整屏 = 桌面闪**（应用层无法消除，已多轮日志验证）
2. **PanGesture 手指出窗会收到 Cancel 断触**；**TYPE_FLOAT 无法局部触摸穿透**（HitTestMode 只在窗口内有效，setWindowMask 只管显示形状）

唯一根治方案：**拆成两个职责分离的窗口**，让每个窗口都「只 move、永不 resize」。

## 目标架构

| 窗口 | 尺寸 | 触摸 | 职责 | resize? |
|------|------|------|------|---------|
| **视觉层** `copy_bubble_view` | 常驻全屏 | `setWindowTouchable(false)` 整窗穿透 | 渲染气泡外观、捕获波纹、休眠形变、面板、吸入区提示——所有**纯视觉**内容 | **永不**（创建时铺满一次） |
| **交互层** `copy_bubble_touch` | ~48×48，跟随气泡 | `setWindowTouchable(true)` | 透明的手势热区，承载 PanGesture/TapGesture；停靠时只挡气泡那 48×48，下层其余区域可点 | **永不**（只 moveWindowTo） |

**面板展开**：复用视觉层窗口渲染面板（它已全屏），面板的点击交互通过交互层窗口的坐标转发，或面板点击改用一个临时第三窗口。**初版先简化：面板行点击通过 AppStorage 信号 + 视觉层短暂开 touchable 实现**（面板是偶发、短暂模态，此期间不要求下层可点）。若实测仍有问题再加第三窗口。

**关键：两个窗口都永不 resize → 永不闪。** 交互层只 `moveWindowTo` 跟随气泡（与 legacy `BubbleWindow_legacy.moveTo` 同款，已验证可行）。

## 为什么不闪

- 视觉层：创建时 apply 全屏一次，之后 `applyRect` 去重跳过，运行期零窗口操作
- 交互层：拖拽/停靠只调 `moveWindowTo`（纯位移，无 surface 重建），不调 `resize`
- 没有任何 `resize` 调用发生在运行期 → 没有 surface 重建 → 没有桌面闪烁

## 为什么下层能点

- 视觉层 `setWindowTouchable(false)`：整窗触摸穿透，全屏但不挡下层 app
- 交互层只有 48×48 且跟着气泡走：气泡本来就在那 48×48，多挡的只是气泡自身覆盖的区域，下层 app 在气泡之外完全可点

## 拖拽为何不断触

交互层在 `onActionUpdate` 里每帧 `moveWindowTo` 跟随手指，窗口始终把手指罩在 48×48 热区内（与 `BubbleWindow_legacy.moveTo` 完全同款，已在 legacy 验证可行）。无需全屏也能持续追踪手势。

## 实现步骤

### 1. `BubbleWindowManager.ets` — 改造为双窗口管理器
- 新增第二个窗口句柄 `touchWin`，窗口名 `copy_bubble_touch`
- `create()` 同时创建两个窗口：
  - 视觉层：`setWindowTouchable(false)` + `setWindowFocusable(false)`，apply 全屏一次
  - 交互层：`setWindowTouchable(true)` + `setWindowFocusable(false)`，初始 48×48，加载新页 `pages/BubbleTouchPage`
- 新增 `moveTouchWindow(x, y)`：只 `moveWindowTo`，给交互层用（拖拽/停靠跟随气泡）
- `applyRect()` 保留但仅用于视觉层（去重后基本 no-op）
- `destroy()` 销毁两个窗口

### 2. 新增 `pages/BubbleTouchPage.ets` — 交互层 UI
- 透明 Stack，48×48，承载手势（PanGesture + TapGesture）
- 手势逻辑从 `FloatBubble` 迁移过来：拖拽更新坐标 → 调 `mgr.moveTouchWindow()` 同步移动窗口 + 通过 AppStorage 信号通知视觉层更新气泡位置
- 点击 → 通过 AppStorage 信号通知视觉层开/关面板
- 用 AppStorage key（新增 `cb_bubble_x`/`cb_bubble_y`/`cb_tap`/`cb_dragging`）做两窗口间通信（已有 `AppKeys` 模式可复用）

### 3. `FloatBubble.ets` — 改为纯视觉 + 信号驱动
- 删除手势（移到交互层），改为 `@StorageLink` 监听 x/y/dragging/tap 信号驱动渲染
- 删除 `HitTestMode.Transparent`（视觉层窗口本身已不可触摸，不需要）
- 面板点击：保留 `onPick`，面板行的 onClick 通过 AppStorage 通知交互层或直接处理（面板展开期间视觉层短暂开 touchable）

### 4. `AppKeys.ets` — 新增跨窗口信号 key
- `BUBBLE_X`、`BUBBLE_Y`、`BUBBLE_DRAGGING`、`BUBBLE_TAP` 等

### 5. `DockEngine.ets` — `windowRect()` 简化
- 视觉层恒全屏（保留当前实现）
- 新增 `touchRect(x, y)`：返回气泡 48×48 热区矩形（供交互层窗口定位）

### 6. `main_pages.json` — 注册 `pages/BubbleTouchPage`

### 7. 测试 `DockEngine.test.ets`
- 更新 `windowRect` 断言（视觉层恒全屏，已改）
- 新增 `touchRect` 断言

## 风险与验证点

1. **跨窗口手势追踪**：交互层 48×48 窗口 + 每帧 moveWindowTo 是否真的不断触。legacy 同款已验证可行，但需真机确认。**若断触**：退路是交互层拖拽时扩到全屏（仅此一次 resize 可接受，因拖拽是连续动作中间闪一帧不易察觉）——但这希望避免。
2. **两窗口 z-order**：需确保交互层在视觉层之上（后创建的 TYPE_FLOAT 默认在上，且交互层需能收到触摸）。若 z-order 有问题用 `setSubWindowZLevel` 调整。
3. **面板点击穿透**：面板展开期间视觉层需短暂可触摸接收行点击。此期间下层不可点是可接受的（短暂模态）。
